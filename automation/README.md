# 자동화: 주간 팝업 브리핑 (Apps Script)

매주 월요일 11:00(KST)에 이번 주 시작·마감 팝업과 정보가 빈 팝업을 **내 메일**로 받는다.
GitHub Actions 가 매일 08:40 에 Notion 데이터를 `data/cafes.json` 으로 올린 뒤라서 최신 데이터로 만든다.

```
매일 08:00 Notion 수집(Claude 예약 작업, Notion MCP)
  → 매일 08:40 GitHub Actions: Notion → Supabase(설정 시) · data/cafes.json 커밋
  → 월 11:00 Apps Script: data/cafes.json → 주간 브리핑 메일 + 시트 기록
```

## 왜 이렇게 만들었나 (PO 판단)

| 고민 | 결정 | 이유 |
| --- | --- | --- |
| 북마크한 사람마다 알림을 보낼까? | **안 보낸다.** 운영자(나) 한 명에게만 보낸다 | 앱은 로그인이 없고 이메일을 저장하지 않는다는 원칙이 있다. 사용자 메일을 모으면 민감정보 저장·관리 부담이 생긴다 |
| 받는 주소를 어디에 둘까? | 코드·시트 어디에도 적지 않는다. 실행할 때 `Session.getEffectiveUser()` 로 읽는다 | 저장소에 이메일이 올라갈 일이 없다 (커밋 전 검사 훅도 이메일을 막는다) |
| 메일 내용이 틀리면? | 데이터에 있는 값만 쓰고, 빈 값은 '확인 필요' 칸으로 모은다. 맨 아래에 "공식 공지에서 다시 확인" 문구 | 자동 발송 콘텐츠의 사실 오류 방지 |
| n8n 을 쓸까? | Apps Script | 서버를 따로 띄우지 않아도 되고, 구글 계정만 있으면 무료로 매주 돈다 |

## 설치 (5분)

1. https://script.google.com → **새 프로젝트**. (기록을 시트에 남기려면 구글 시트를 하나 만들고 `확장 프로그램 → Apps Script` 로 연다)
2. `Code.gs` 내용을 지우고 `automation/weekly_briefing.gs` 를 통째로 붙여넣고 저장.
3. 위쪽 함수 선택에서 `weeklyBriefing` → **실행** → 권한 승인(메일 보내기 · 외부 URL 읽기 · 시트).
   - 내 메일함에 브리핑이 오면 성공.
4. 함수 선택에서 `installTrigger` → **실행**. 이제 매주 월요일 11시에 자동으로 온다.
   - 왼쪽 시계 아이콘(트리거)에서 확인할 수 있다.

## 실패하면

| 증상 | 원인 · 해결 |
| --- | --- |
| `데이터를 못 읽었습니다 (HTTP 404)` | 저장소가 비공개거나 `DATA_URL` 의 브랜치 이름이 다름 |
| `데이터가 비어 있습니다` | `data/cafes.json` 이 빈 목록. Actions 실행 기록 확인 |
| 메일이 안 옴 | 트리거 실행 기록(왼쪽 '실행')에서 오류 확인. 하루 메일 한도(무료 100통)는 주 1통이라 넉넉함 |
