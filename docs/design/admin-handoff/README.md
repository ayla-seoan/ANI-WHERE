# ANI:WHERE 관리자 페이지 디자인 핸드오프

Claude Design 캔버스의 「관리자 확정안」(1안 할 일 먼저 + 2안 사이드바·지표 혼합) 8페이지를 코드로 옮기기 위한 묶음입니다.
원본 캔버스: https://claude.ai/artifact/Jf5jKYdTmNj3eXCapg67dD (본인 계정에서만 열림, 맨 아래 '관리자 확정안' 줄)

## 1. 이 묶음 읽는 법

- `screens/AdmX-*.dc.html` 은 **디자인 시안**입니다. 그대로 붙여 넣는 코드가 아닙니다.
  - `{{ 값 }}`, `<sc-for>`, `<sc-if>`, `<x-dc>` 는 Claude Design 캔버스 전용 문법입니다. 반복되는 줄 · 카드의 예시 데이터는 파일 맨 아래 `<script>` 의 `renderVals()` 배열에 있습니다.
  - 색 · 간격 · 모서리 · 글꼴 크기는 요소의 `style="…"` 에 그대로 적혀 있으니 값을 읽어 옮기면 됩니다.
  - 브라우저로 직접 열면 반복 영역이 비어 보일 수 있습니다. 모양은 원본 캔버스에서 확인하세요.
- `tokens.json` = 기존 ANI:WHERE 디자인 시스템 토큰. `assets/` = 로고(배경 투명) · 토끼 마스코트.

## 2. 무엇이 바뀌나 (지금 관리자 대시보드 대비)

1. **위 탭 → 왼쪽 사이드바.** 어두운 사이드바(#1f2a27), 고른 메뉴는 민트 바탕(#5eead4) + 진한 글자. 삭제 요청 대기 수는 메뉴 옆 빨간 배지. 맨 아래 바로가기(Claude 예약 작업 · Supabase 데이터 보기 · 서비스로 돌아가기).
2. **새 첫 화면 '한눈에 보기'.** 들어오자마자 "오늘 처리할 일 N건" — 삭제 요청은 그 자리에서 승인/거부, 정보 빠진 팝업은 '수정하기'로 바로.
3. 나머지 7개는 지금 있는 탭(팝업 현황 · 이용 지표 · 삭제 요청 · 알림 관리 · 회원 정보 · 원본 데이터 · 사용자 테스트)을 더 잘 보이게 다시 배치.

## 3. 페이지별 내용 → 지금 코드

| 시안 | 페이지 | 주요 구성 | 지금 코드 |
| --- | --- | --- | --- |
| `AdmX-1Home` | 한눈에 보기 (**새로**) | 처리할 일 목록 · 수집 상태 · 숫자 카드 5개 · 북극성 완결률 · 일별 접속 · 최근 활동 | `common/admin.py` 숫자 카드 + 각 탭 데이터 재사용 |
| `AdmX-2Popups` | 팝업 현황 | 상태 필터 카드 · 주간 간트(오늘 빨간 선, '확인' 표시) · 상태별 칸반 | 기존 간트 · 칸반 |
| `AdmX-3Usage` | 이용 지표 | 신규 → 접속 → 탈퇴 흐름 · 날짜별 막대(줄마다 따로 눈금) · 가입 방법 · 북마크 많은 팝업 · 물어보기 많이 한 질문 | 기존 이용 지표 + 북마크 · 물어보기 기록 |
| `AdmX-4Delete` | 삭제 요청 | 대기/처리 완료 탭 · 펼친 요청 카드(요청자 랭크 · 사유 · 처리 사유 입력 · 승인/거부/기간만 고치기) · 처리 기록 표 | 기존 삭제 요청 승인/거부 |
| `AdmX-5Alerts` | 알림 관리 | 규칙 표(며칠 전부터 · 최대 개수 · 켜기) · 회원에게 보이는 미리보기 · 새 공지 · 보낸 공지 | `alert_rules` (007) |
| `AdmX-6Members` | 회원 정보 | 받는/받지 않는 정보 · 회원 표(후기 도장 랭크 · 가입 방법 · 최근 접속 · 권한) | 기존 회원 정보 |
| `AdmX-7Raw` | 원본 데이터 | 표 고르기 탭 · 지금 내용만/모든 기록 · CSV · Supabase 열기 | 기존 원본 데이터 |
| `AdmX-8Test` | 사용자 테스트 | 검증된 응답 수 배너 · 과제별 성공률 · 같은 사람 비교 · 막힌 곳 · 측정 한계 | `stats.survey_compare` · `survey_summary` |

Streamlit 과 공개 웹(`web/`) 관리자 화면을 **같이** 바꿉니다.

## 4. 실제 값 vs 예시 값

- 실제(README 기준): 완결률 85.4% · 1차 70.0%, 팝업 124곳, 사용자 테스트 검증된 응답 0명, 수집 매일 08:40, 종료 팝업 월요일 00:10 정리, 블로그 한 달 한도 30,000번.
- 그 밖의 숫자(회원 수 · 접속 수 · 요청 내용 · 닉네임 · 그래프 값)는 **예시**입니다. 실제 데이터에 연결하세요.
- 사용자 테스트는 응답이 0명이면 배너 + 빈 상태를 보여 주고, 그래프는 응답이 생긴 뒤에만 그립니다 (예시 숫자를 실제 화면에 쓰지 않기).

## 5. 색 · 차트 규칙

- 간트: 예정 #2c5bc5 · 진행 #0d9488 (색 조합 검사 통과), 종료는 색 대신 **점선 테두리** #9aa5a1. 팝업 이름은 막대 안이 아니라 왼쪽 칸에.
- 오늘 표시: 빨간 선 #e5484d. 급한 것(삭제 요청 대기): #c0313f.
- 사용자 테스트 3계열: 평소 방법 #c77a12 · 1차 #2c5bc5 · 2차 #0d9488 (검사 통과), 범례 + 막대 위 숫자.
- 막대는 위쪽만 4px 둥글게, 이중 축 금지(크기가 다른 숫자는 줄을 나눠 따로 눈금).

## 6. 새 기능 / 결정 필요

- '한눈에 보기' 페이지 자체가 새 화면.
- 삭제 요청의 **'기간만 고치기'** 버튼 (요청을 거부하고 수정 화면으로).
- 회원 표의 **후기 도장 랭크** — 랭크 기준이 확정되기 전에는 칸을 숨기거나 '후기 수'만 표시.
- 알림 규칙 **'랭크 승급 (제안)'** — 꺼진 상태로 표시만.
- **강제 탈퇴 · 파기** — 아직 없는 기능이라 비활성 버튼('공개 전 보완 예정')으로만.
