# Notion 트래커 규칙

ANI:WHERE 의 팝업 데이터는 두 단계로 들어옵니다.

1. **주간 수집 (예약 작업)** — 매주 월요일 RE:CAL 등에서 행사를 모아 Notion **'🎀 애니 팝업·콜라보 트래커'** DB 에 쌓습니다.
2. **앱 가져오기** — 앱이 그 Notion DB 를 읽어 지도(`data/cafes.json`)에 넣습니다. 코드는 `common/notion_sync.py`.

이 문서는 두 단계의 규칙을 함께 적습니다. 1단계 규칙의 원본은 예약 작업의 지시문이고, 바뀌면 이 문서도 같이 고칩니다.

---

## 1. 주간 수집 (예약 작업)

| 항목 | 값 |
| --- | --- |
| 이름 | 애니 팝업·콜라보 주간 수집 |
| 언제 | 매주 월요일 오전 8:43 (한국 시간) |
| 어디에 저장 | Notion DB '🎀 애니 팝업·콜라보 트래커' (data source `08b1da83-4ff5-4c5a-af4c-f6b3d682461b`) |
| 관리 | claude.ai 예약 작업(Routine). 상태·다음 실행은 Claude Code 에서 확인 |

### 1-1. DB 구조: 행사 × 지점 = 1행

- 행사 하나가 여러 곳에서 열리면 **지점 수만큼 행**을 만듭니다. 지도 핀 하나 = 한 행.
- 각 행의 장소명·주소·위도·경도는 그 지점 값, 나머지(작품명·기간·팝업소개·특전·굿즈·이미지·링크 등)는 행사 공통값을 복사합니다.
- **지점** 칸에는 그 행사의 **형제 지점 전체**를 한 줄에 하나씩 `지점명|위도|경도|주소` 로 적습니다 (좌표를 모르면 `지점명|(좌표없음)|지역명`).
- 같은 건물·같은 층의 다른 표기('AK&홍대', '애니메이트 카페 홍대점', 'Gratte 홍대')는 한 지점으로 합칩니다.
- RE:CAL 은 대표 지점 좌표만 주므로, 대표 지점이 아닌 행은 이벤트 칸에 "기간은 <대표지점> 기준 복사" 라고 남깁니다.

### 1-2. 무엇을 모으나

- 후보: `recal.kr/ko/c/offline` (보조 `recal.kr/ko/c/anime`) 목록에서 **슬러그만** 뽑고, 내용은 반드시 상세 페이지(`recal.kr/ko/e/offline/<슬러그>`)에서 읽습니다. 목록과 상세가 다르면 상세를 따릅니다.
- **포함**: 콜라보 카페, 팝업스토어, 애니 전시·원화전, 굿즈샵 한정(Gratte, 페어 in animate), 대형 행사(AGF·코믹월드·일러스타 위크·코스앤코믹·IP 페스티벌), 게임 IP 의 콜라보·팝업.
- **제외**: 게임 업계 행사(지스타, 출시·사전예약, 세일, 업데이트, e스포츠), 버튜버·스트리머 행사. 애매하면 제외.
- **범위**: 오늘 진행 중이거나 3개월 안에 시작. 이미 끝난 행사는 새로 모으지 않습니다.
- **연도 검증**: 상세의 요일이 그 해 실제 요일과 맞는지 대조하고, 다르면(다른 해 행사) 저장하지 않습니다.

### 1-3. 링크 4칸 (서로 겹치지 않게)

| 칸 | 들어가는 것 |
| --- | --- |
| 공식공지 | 상세의 '이번 회차' 주소 |
| 주최링크 | 상세의 '주최' 주소 (공식공지와 같으면 비움) |
| 출처 | 실제로 확인한 경로. 기본은 RE:CAL 상세 주소 |
| 참고링크 | 위 세 칸에 없는 추가 링크 (기사, 예약 페이지 등) |

겹치면 공식공지 > 주최링크 > 출처 > 참고링크 순으로 아래 칸을 지웁니다. **소개출처**는 이 규칙과 별개입니다 (공식공지와 같아도 됨).

### 1-4. 팝업소개 · 소개출처

- RE:CAL 의 소개·메타 설명은 날짜·장소를 되풀이한 자동 문구라 **쓰지 않습니다** (들어 있으면 비움).
- 공식공지·주최링크·참고링크의 **기사나 주최 공식 페이지**에서 행사 설명을 **요약하지 않고 전부** 옮깁니다.
- 읽을 수 없는 곳(x.com, instagram.com, game.naver.com, n.news.naver.com, agfkorea.com, animate.co.kr, bluearchive.nexon.com, toonique.co.kr)뿐이면 팝업소개·소개출처를 비워 둡니다.
- 형식
  - 문장마다 줄을 바꾸고 끝 마침표는 뺍니다 (날짜·전화번호·도메인 안의 점은 그대로).
  - `[체험]` `[굿즈]` `[공연]` `[입장]` `[운영 안내]` 같은 머리말로 묶습니다.
  - 페이지에 없는 항목은 끝에 `※ 입장료와 가격은 기사에 없다` 처럼 한 줄.
  - 마지막 줄은 `(출처: <매체·사이트 이름>)`. **그 페이지 주소는 소개출처 칸**에 넣고 본문에는 적지 않습니다.
  - 공식 페이지에 홍보 문구 한 줄뿐이면 그 문구를 따옴표로 옮기고 "※ 공식 페이지에 이 문구 외 상세 소개 없음".
  - Notion 글자 제한 2,000자. 넘치면 덜 중요한 안내부터 줄입니다.
- 다지점 행사는 같은 소개를 모든 지점 행에 복사합니다.
- 이미 팝업소개가 차 있는 행은 덮어쓰지 않습니다.
- 소개에서 굿즈·특전·캐릭터·이벤트·주소(층수 포함)·좌표(숫자가 적혀 있을 때만)를 뽑아 그 칸에도 채웁니다. 없으면 "확인 필요". 지어내지 않습니다.

### 1-5. 검수상태 · 상태

- **검토 완료** = 작품명 / 유형 / 장소명 / 기간(시작+종료) / 출처가 모두 있고 아직 안 끝난 행사.
- **검토 필요** = 시작일·종료일이 불명확하거나 위 필수 정보가 하나라도 빈 행사. **이 두 가지 말고는 '검토 필요' 를 붙이지 않습니다** (소개·좌표·이미지·특전 등이 비었거나 분리 행인 것은 사유가 아님).
- 상태: 기간 안이면 진행중, 시작 전이면 예정, 종료일이 지나면 종료로 바꿉니다.
- 수집일: 실행한 날.

### 1-6. 중복·업데이트

- **작품명 + 장소명 + 기간**이 같으면 새 행을 만들지 않고, 비어 있거나 "확인 필요" 인 칸만 채웁니다.
- 같은 작품·같은 장소라도 기간이 다르면 다른 회차라 별도 행입니다.
- 사용자가 Notion 에 직접 올린 이미지, 사람이 직접 적은 값은 건드리지 않습니다.
- 휴지통에 있는 행은 되살리지 않습니다 (일부러 지운 것).
- 이미지는 RE:CAL(`recal.kr/images/item/...webp`)을 쓰고, 없으면 popga·popply·dueple·spotts 상세의 대표 이미지나 기사 이미지 중 기간이 맞는 것만 씁니다. 못 구하면 비워 둡니다.
- 좌표는 확인된 값(지시문의 '알려진 지점 좌표' 목록)을 재사용하고, 추측해서 만들지 않습니다.
- 저장 뒤 한글이 바뀌지 않았는지 확인합니다 (예전에 '뚝섬로' → '리섬로', '컬렉션' → '컴렉션', '젤다' → '젠다' 사례).
- 마지막에 링크 4칸 중복이 0건인지, 소개는 있는데 세부 칸이 빈 행이 없는지 확인하고 보고합니다.

## 2. 앱 가져오기 (`common/notion_sync.py`)

### 2-1. 언제

- **매주 자동 (GitHub Actions)**: `.github/workflows/notion-sync.yml` 이 **매주 월요일 오전 10:00 (KST)** 에 돕니다.
  주간 수집(08:43, 약 20분)이 끝난 뒤입니다.
  1. Notion API 로 DB 전체를 읽고 (`scripts/notion_import.py`)
  2. 새 팝업 추가 · 빈 이미지 채움 · 팝업 소개 맞춤 · 기간 끝난 팝업 내림
  3. 바뀐 게 있으면 `data/cafes.json` 과 새 포스터(`static/uploads/`)를 커밋해 `main` 에 올립니다 → Streamlit Cloud 가 다시 배포
  - 필요한 저장소 Secret: `NOTION_TOKEN` (필수), `KAKAO_REST_API_KEY` (선택, 좌표 없는 곳 위치 찾기)
  - 저장소 **Actions** 탭 → 'Notion 주간 가져오기' → **Run workflow** 로 아무 때나 바로 돌릴 수 있습니다. 실행 기록에 추가·건너뜀 개수가 남습니다.
- **앱을 열 때**: `.env` 에 `NOTION_TOKEN` 이 있으면 메인 화면을 열 때도 가져옵니다. 최대 1시간에 한 번(`data/notion_sync.json` 에 마지막 시각).
- **손으로**: `python scripts/notion_import.py --dry` 로 결과만 본 뒤 `python scripts/notion_import.py` 로 넣습니다.
  키가 없으면 Notion 연결(Claude 의 Notion 도구)로 표를 읽어 같은 함수(`import_rows`, `sync_intros`)에 넣습니다.

#### NOTION_TOKEN 만들기 (한 번만)

1. https://www.notion.so/profile/integrations 에서 **새 통합(Internal)** 을 만들고, 기능은 **콘텐츠 읽기**만 켭니다. 만들면 나오는 키(`ntn_…`)를 복사합니다.
2. Notion 에서 '🎀 애니 팝업·콜라보 트래커' DB 페이지 → 오른쪽 위 `⋯` → **연결** → 방금 만든 통합을 추가합니다. (이걸 안 하면 읽을 수 없음)
3. GitHub 저장소 → Settings → Secrets and variables → Actions → **New repository secret** 이름 `NOTION_TOKEN`, 값에 키를 붙여 넣습니다.
4. 키는 `.env` 와 Secret 에만 둡니다. 코드·문서에 적거나 커밋하지 않습니다.

### 2-2. 어떤 행을 가져오나

| 조건 | 처리 |
| --- | --- |
| 검수상태 **검토 완료** | 가져온다 |
| 검수상태 **검토 필요** | 가져오지 않는다 |
| 기간(시작·종료), 작품명, 장소명 중 빈 것이 있음 | 가져오지 않는다 |
| 이미 끝난 행사, 위치를 못 찾은 곳 | 가져오지 않는다 (등록할 때와 같은 검사) |
| 예전에 가져왔다가 지도에서 내린 행사 | 다시 가져오지 않는다 |

### 2-3. Notion 칸 → 앱 칸

| Notion 칸 | 앱 칸 | 규칙 |
| --- | --- | --- |
| 작품명 | 작품 | 끝의 괄호는 뺀다 (`프로젝트 세카이 (프로세카)` → `프로젝트 세카이`) |
| 장소명 | 카페명 | 한 칸에 여러 곳이 적혀 있으면 첫 곳만 (`… 합정점 / 부산 서면점` → 합정점) |
| 주소 | 주소 | 비어 있으면 장소명으로 위치를 찾는다 |
| 위도 · 경도 | 지도 위치 | 있으면 그대로, 없으면 주소로 찾는다 |
| 기간 | 시작일 · 종료일 | |
| 캐릭터 | 캐릭터 | `,` `·` 로 나눈다 |
| 특전 · 굿즈 | 특전 · 굿즈 | `/` `,` 로 나눈다 |
| 이벤트 · 특전 문구 | 이벤트 추가 정보 | 간편등록과 같은 낱말 표로 고른다 |
| 공식공지 · 출처 · 주최링크 · 참고링크 | 참고 웹사이트 | 이 순서로 모으고 겹치는 주소는 한 번만. `recal.kr` 은 맨 뒤 (다른 사이트가 없으면 첫 번째). 최대 5개 |
| 이미지 · 파일과 미디어 | 포스터 · 추가 이미지 | 내려받아 저장. 첫 장이 포스터 |
| 팝업소개 | 팝업 소개 | 2-4 규칙 |
| 소개출처 | 소개 출처 (`intro_src`) | 첫 주소만. 상세 화면 팝업 소개 상자 오른쪽 아래 **출처 보기** 버튼. 소개가 없으면 출처도 두지 않는다 |
| 지점 | — | 형제 지점 목록이라 쓰지 않는다 (2-6) |

- '확인 필요', '미확인' 은 빈칸으로 봅니다.
- 앱 기록의 방법은 **AI 자동 수집**, 수정한 사람은 **AI** (수정 이력에 그대로 보임).
- 기록 메모(`note`) 끝에 `| notion:<페이지 번호>` 를 붙입니다. 앱에서 고쳐 저장해도 이 표시는 남깁니다 (`_keep_notion`). 다음 가져오기 때 같은 팝업으로 알아보는 열쇠입니다.

### 2-4. 팝업 소개

- Notion 서식을 평문으로 정리합니다: `<br />` → 줄바꿈, `\[` `\~` 같은 이스케이프 → 원래 글자, `[글자](주소)` → 글자만.
- 줄 맨 앞의 `[체험]` 같은 머리말은 상세 화면에서 민트색 굵은 글씨로 보입니다.
- **전화번호·이메일은 저장하지 않습니다.** 휴대폰·일반 전화(02-, 0507- 등)·이메일이 든 줄(보통 문의처)은 통째로 뺍니다.
- 최대 3,000자.
- **Notion 이 기준입니다.** Notion 에서 소개가 바뀌면 앱도 바꾸고, 지우면 앱에서도 비웁니다 (출처도 같이).
- 다만 **사람이 앱에서 직접 쓰거나 고친 소개는 덮어쓰지 않습니다** (지금 소개를 마지막으로 바꾼 기록의 수정한 사람이 AI 가 아니면 그대로).
- 이미 있는 팝업은 소개·출처와 빈 이미지만 맞추고, 다른 칸은 건드리지 않습니다.

### 2-5. 같은 팝업인지 알아보는 순서

이미 앱에 있으면 새로 만들지 않습니다. 위에서부터 하나라도 맞으면 같은 팝업입니다.

1. 같은 Notion 페이지 (예전 기록까지 포함해 `notion:<번호>` 표시가 있음)
2. 같은 작품 + 같은 카페명 (띄어쓰기만 다른 것도 같게 봄)
3. 작품명이 한쪽이 다른 쪽을 품고 + 기간이 겹치고 + 위치가 500m 안이거나 도로명 주소가 같음
4. 같은 작품 + 시작일·종료일이 똑같고 + 같은 시·구 (매장 이름·주소 표기가 달라도. 예: 'SMG CAFE 신촌점' 과 '현대백화점 신촌점 유플렉스')

**알려진 한계**: 같은 건물에서 기간이 겹치는 같은 작품의 **다른** 행사는 3번에 걸려 하나로 묶일 수 있습니다
(예: 주술회전 BOX cafe&space 홍대점 09.23~12.01 과 주술회전 5주년 문화제 페어 애니메이트 카페 홍대점 10.24~11.15).
1단계는 '작품명 + 장소명 + 기간' 으로 다른 회차를 구분하지만, 앱은 작품명 괄호를 떼고 보기 때문입니다. 이런 경우는 가져오기 결과를 보고 따로 넣습니다.

### 2-6. 여러 지점

- 1단계가 지점마다 행을 나눠 주므로 앱은 **행 그대로** 가져옵니다. 이 행의 장소명이 '지점' 목록 안에 있으면 형제 목록일 뿐이라 나누지 않습니다.
- 장소명이 목록에 없는 행(예전 방식으로 한 행에 여러 지점을 적은 경우)만 지점마다 나눕니다. 첫 지점은 원래 페이지 번호, 둘째부터는 `페이지번호-2` 처럼 번호를 붙입니다. 좌표가 `(좌표없음)` 이면 주소로 찾습니다.

### 2-7. 저장 방식

- 저장소는 append-only 입니다. 고치거나 채울 때도 기존 행을 덮어쓰지 않고 새 행을 쌓습니다.
- 가져온 내용이 틀렸으면 상세 → 수정하기 → 수정 이력에서 **이 버전으로 돌아가기** 로 되돌립니다.

## 3. 두 단계가 다른 점 (헷갈리기 쉬운 것)

| 주제 | 1단계 (Notion 에 쌓을 때) | 2단계 (앱으로 가져올 때) |
| --- | --- | --- |
| 팝업소개 덮어쓰기 | 이미 차 있으면 덮어쓰지 않음 | Notion 기준으로 맞춤 (사람이 앱에서 쓴 소개만 예외) |
| 소개 글자 수 | 2,000자 (Notion 제한) | 3,000자 |
| 전화번호·이메일 | 소개에 그대로 둘 수 있음 | 그 줄을 빼고 저장 |
| 같은 행사 판단 | 작품명 + 장소명 + 기간 | 2-5 의 4단계 |
| 검토 필요 행 | 저장함 | 가져오지 않음 |
| 지점 | 지점마다 행, '지점' 칸에 형제 목록 | 행 그대로, '지점' 칸은 쓰지 않음 |
