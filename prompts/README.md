# 프롬프트 기록

실제 프롬프트 파일은 앱이 읽는 자리인 `common/prompts/<이름>.<버전>.txt` 에 있다. 여기는 **무엇을 왜 바꿨는지** 적는 곳이다.
규칙: 프롬프트는 덮어쓰지 않고 새 버전 파일을 만든다. 이미 있는 버전을 고치려 하면 `.claude/hooks/edit_rules.py` 훅이 막는다.
어떤 버전을 쓸지는 `.env` 의 `<이름>_PROMPT_VERSION` (예: `CAFE_PROMPT_VERSION=v2`). 모든 호출은 `logs/runs.jsonl` 에 버전과 함께 남는다.

| 프롬프트 | 쓰는 곳 | 지금 버전 |
| --- | --- | --- |
| `cafe` | 등록하기 → 공지 글 붙여넣기 → 칸 자동 채우기 | v2 |
| `ask` | 팝업에게 물어보기 (`/ask`) | v1 (2차 새로 만듦) |
| `priority` | `app_priority.py` (1차 실습, 2차 범위 밖) | v1 |

## cafe: v1 → v2

| | v1 | v2 |
| --- | --- | --- |
| 대상 | 생일 카페 공지 | **애니 캐릭터 팝업·콜라보 카페** 공지 |
| 작품명 | 규칙 없음 | 해시태그·『』「」 안의 이름을 작품명으로, '콜라보·팝업·카페' 같은 말은 뺌 |
| 캐릭터 | 규칙 없음 | **원문에 이름이 나온 캐릭터만.** 작품 지식으로 채우지 말 것 |
| 기간 | "11/1~11/7" 처럼 짧은 행사 위주 예시 | "11.1-30", "한 달간" — 팝업은 몇 주~두세 달이라는 설명 추가 |
| 특전/굿즈 | 무료 vs 유료 | + 콜라보 메뉴(음료·디저트)는 어느 쪽에도 넣지 않음 |
| 장소 | 카페가 여러 곳이면 나눔 | "매장"으로 일반화, 백화점 층수 같은 약식 주소 예시 추가 |

**왜 바꿨나**
- 서비스 주제를 생일 카페 → 애니 팝업으로 바꿨다 (`data/cafes.birthday-backup.json` 이 1차 초기 데이터). 생일 카페용 v1 에는 작품명·캐릭터 칸 규칙이 없었다.
- v2 에 더한 규칙(작품명에서 꾸밈말 빼기, 원문에 없는 캐릭터 채우지 않기, 긴 기간 표기)은 팝업 공지에서 생길 수 있는 오류를 막으려는 것이다.
- ⚠️ **TODO (본인 작성):** v1 → v2 를 바꾸게 만든 실제 입력·출력 사례를 `docs/ai-mistakes.md` 에 적고 여기에 링크한다. `samples/tweets_edge_cases.txt` 로 v1·v2 를 같은 입력에 돌려 비교하면 (`CAFE_PROMPT_VERSION` 만 바꿔서) 전후 수치가 된다. 사례 없이 이유만 적으면 평가에서 근거로 인정받기 어렵다.

## ask: v1 (새로 만듦)

검색(RAG)으로 고른 **후보 팝업 목록만** 근거로 답하게 하는 프롬프트.

| 규칙 | 왜 |
| --- | --- |
| 후보에 없는 팝업·주소·날짜를 지어내지 말 것, 쓴 팝업 id 를 `used_ids` 에 | 지어내기 방어. 코드(`ask.answer`)가 후보에 없는 id 를 한 번 더 지운다 |
| 딱 맞는 후보가 없으면 먼저 그렇게 말하고 `confidence=low` | "없다"를 말 못 하는 챗봇이 가장 위험 — 사용자가 헛걸음한다 |
| 끝난 팝업은 "종료"라고 밝힐 것 (오늘 날짜를 함께 줌) | 지난 팝업을 진행 중처럼 안내하는 실수 방지 |
| 팝업과 관계없는 질문은 거절 | 범위 밖 질문에 답하다 사실 오류가 나는 것 방지 |
| 전화번호·이메일·계좌 금지 | 민감정보 원칙 (입력은 `guard.mask` 로 먼저 가림) |

**검색 쪽은 프롬프트가 아니라 규칙(`common/ask.py`)으로 고쳤다.** v1 규칙에서 '열려 있는', '시작하는' 같은 서술어를 검색어로 받아 0건이 나오는 문제를 평가로 찾았다 → 92% → 100% (`docs/ask-eval.md`). 프롬프트 v2 는 상호 테스트에서 받은 질문으로 AI 답의 오류가 확인되면 만든다.
